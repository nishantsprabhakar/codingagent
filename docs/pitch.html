Code generation is abundant. Trustworthy delivery is not.

  • Generation is no longer the bottleneck. Teams lose time validating patches, undoing regressions, reconstructing context and policing tool access.
  • Model lock-in compounds cost. Most agent products fuse the workflow to one model, one cloud and one commercial roadmap.
  • Autonomy without evidence creates hidden work. A fluent answer is not a passing build, a safe mutation or a recoverable change.
  • Wrexlyn productizes the missing layer: governed execution, deterministic verification, evidence and recovery around whichever model the customer chooses.
03 / 21

One control plane from intent to verified outcome

Wrexlyn owns the execution chain above the model: context acquisition, governed action, objective checks, failure recovery and evidence-grade delivery.

  • Understand: ranked code search, symbols, repository structure and Git history ground the task before edits begin.
  • Control: every mutation is classified, permission-gated and protected by binary-safe checkpoints.
  • Prove: project-native tests, builds and deterministic artifact checks outrank the model's narrative confidence.
  • Recover: independent critique, bounded repair, NCP diagnosis and isolated Best-of-N attempts turn failure into a controlled workflow.

The Nishant Convergence Protocol

A weak or free model is rarely bad at a first attempt. It's bad at self-correcting when that attempt fails — a generic “try again” gets a near-identical repeat, or a thrash to something unrelated. NCP targets exactly that moment.

1

Divergent diagnosis — once a plain repair attempt has already failed, two independently-framed root-cause diagnoses run in parallel from the same failure evidence.

2

Pairwise adjudication — a dedicated call judges the two diagnoses against each other, not in isolation — measurably more reliable than either self-scoring.

3

Lesson-steered — the project's learned lessons are ranked by relevance and foregrounded directly in both diagnosis prompts, not left as passive context.

4

Formalized score — repair rounds used, adjudication margin, and any lesson recurrence combine into one reproducible confidence number.

Honest scope: this closes the reliability gap on checkable tasks — code, documents — not raw reasoning capability. And it's adaptive: the ensemble only runs once a first attempt has already failed, so it costs nothing extra on the common case.

A quality gate the model can't talk its way past

Every document a model writes is a claim about its own work. Wrexlyn doesn't take that claim on faith — it checks the file that actually landed on disk.

  • Deterministic, not another LLM guess — leftover placeholder text (TODO, lorem ipsum, [insert…), jagged tables where a row doesn't match its header, a table or sheet with headers but zero data rows: all caught by plain code, not a second model call that could be just as wrong as the first.
  • Fails closed, then the model fixes it — same turn — a blocked check returns a specific reason, the model reads it and retries immediately. No silent shipping of a half-finished table.
  • Confidence scores stop lying — a document-only turn used to be capped at 60% confidence no matter how clean the output was, because nothing had verified it. Now a turn that passes its quality gate is scored as genuinely verified, not just unchecked-and-hopeful.

This is real irrespective of which integrated, custom or local model generated the file — a weak model's placeholder text or empty section gets caught every time. It can't upgrade a weak model's prose to a strong model's; no checker can. What it does is stop bad structure from ever reaching you.

Not fourteen one-off hacks — one shared discipline

Named, versioned frameworks, not an analyst's gut-check that means something different depending on who's asking.

  • Most quantitative screening in these sectors runs on a judgment call translated into a number that means something different every time it's quoted. These fourteen replace that with named, versioned frameworks in the tradition of the Altman Z-Score and the Piotroski F-Score — the score means the same thing to anyone, this year or next.
  • Every pillar's weight reflects a stated view of what actually drives outcomes in that specific domain — entry price and financial trajectory dominate PE screening; clinical-stage probability of success dominates drug-pipeline triage; empty-mile ratio and cost-per-ton-km dominate logistics diagnostics. Twelve sectors in finance and investing, plus two beyond it — legal contract risk and vendor/third-party security — not one template stretched thin.
  • That's not a coincidence of formatting. A framework that scored every sector the same way would be evidence of a template, not real domain expertise.
19 / 21

Auditable, not a black box

The differentiator isn't any single formula — it's that every claim is checkable.

  • Missing data degrades a confidence rating instead of being silently guessed — a score built from a clean financial model is flagged differently than one built from a two-page teaser deck, and the report says so.
  • Every algorithm ships with a runnable reference implementation, not just a description. The scores on the previous slide were generated by actually running that script against a real worked example — not hand-picked, not illustrative.
  • If a script and its methodology doc ever disagree, the doc wins and the script has a bug. That convention alone is rarer than it sounds in quantitative screening.
20 / 21

Documented like an asset, not a slide deck

Trade secret protection today; the patent question addressed honestly, not oversold.

  • Each algorithm is specified precisely enough — named, versioned, formula-level — to be a serious IP conversation, not just a marketing claim. That specificity is what makes a trade-secret claim defensible in the first place.
  • Patent-eligibility for the scoring models themselves is a separate, harder question under the US Alice/Mayo framework for abstract methods. One algorithm in the set — a logistics consolidation heuristic — has a materially stronger patent-eligibility case, precisely because it's a concrete computational method with a measurable output, not just a scoring-weight scheme.
  • The full methodology is private, not published — available for review under NDA to a serious counterparty, not sitting in a public repo for anyone to copy.
